# Central 一键清理（中央仓库 + Agent 安装残留）

## 背景

用户需要在 Central Skills 页面一键清空中央仓库里的全部 skills，并把它们安装到各 Agent
（Universal、Antigravity、Claude Code、Grok、Kiro、自定义 Agent……）和已登记项目中的副本/链接
一并清理。

现状只有三种删除入口，都不能满足"全部清空 + 残留扫描"：

| 现有入口 | 局限 |
| --- | --- |
| 单个 / 多选批量删除（`delete_central_skills`） | 需要手动全选；只处理 DB 里登记过的安装；不处理项目安装 |
| 按仓库删除（`delete_skill_repository`） | 只覆盖一个仓库 |
| 重置未知来源（`reset_unknown_source_skills`） | 只覆盖无仓库归属的 skill |

更关键的是**数据丢失场景**：DB 被重建/损坏，或中央目录被外部删除后，Agent 目录里会留下指向
中央仓库的 junction / symlink。扫描器只收录含可读 `SKILL.md` 的目录，悬空链接对 DB 和 UI
都不可见，现有任何删除入口都清不掉它们。

## 目标

1. Central Skills 页面提供"一键清理"入口，一次操作完成：中央仓库全部 skills 删除 + 所有
   Agent / 项目中对应安装清理 + 孤儿链接清理。
2. 覆盖"DB 有 / 中央目录有 / Agent 目录有"三者任意组合不一致的情况（见场景矩阵）。
3. 删除前必须先预览，再明确确认；只删除预览中列出且执行时重新校验仍成立的条目。
4. 在数百至数千个 skill、十几个 Agent 的规模下保持可接受的耗时，UI 不冻结，有进度、可取消。

## 非目标

- 不删除用户自建的普通目录（无 DB 记录的 copy 目录永不自动删除）。
- 不触碰 Skills CLI 全局托管（链接目标不在中央仓库内，天然不匹配）。
- 不清理 Rules、Collections 本身、Tag 定义、Saved Views、Skill Usage 历史、Settings、AI Provider
  凭据（skill 行删除时按《Skill Deletion Integrity Contract》级联的关系表除外）。
- 不做"恢复/撤销"能力；推荐用户先用现有 Portable Bundle 导出备份（对话框给入口）。
- 不在本任务内新增 CLI 命令（`skillport-cli central clear` 作为后续任务）。

## 场景矩阵（必须全部覆盖）

| # | DB | 中央目录 | Agent / 项目目录 | 期望行为 |
| --- | --- | --- | --- | --- |
| S1 | 有行 | 有目录 | symlink / junction | 删中央目录 + 删链接 + 删 DB 行 |
| S2 | 有行 | 有目录 | copy（DB 登记） | 默认保留；用户按 Agent 勾选后删除 |
| S3 | 有行 | **目录已丢失** | 悬空链接 | 删 DB 行 + 删悬空链接，不因中央目录不存在而失败 |
| S4 | **无行** | 有目录（未扫描入库） | 有/无链接 | 作为"中央未登记条目"列出，删除目录及指向它的链接 |
| S5 | **无行** | **无目录** | 悬空链接指向中央根 | 作为"孤儿链接"列出并删除，只删链接本身 |
| S6 | 任意 | 任意 | 链接指向**旧中央根**（改过存储位置）或默认根 `~/.skillsmanage/skills` | 识别为 SkillPort 链接并删除 |
| S7 | 任意 | 任意 | 链接指向中央根以外（Skills CLI、用户自建） | 不动 |
| S8 | 任意 | 任意 | 无 DB 记录的普通目录 | 不动，只在预览里计数提示"未托管目录已跳过" |
| S9 | 有行 | 有目录 | Agent 目录 == 中央根（native 共享） | 随中央目录一起删，不重复处理 |
| S10 | 有行 | 有目录 | 项目目录中的 central 链接（`project_skill_installations`） | 删链接 + 删 psi 行（默认开启，可关） |
| S11 | 有未完成日志（崩溃残留 `fs_db_operations`） | — | — | 先执行恢复；恢复失败的条目进入 `failed`，不阻塞其他条目 |
| S12 | 预览后、执行前新增了 skill / 链接 | — | — | 新增条目**不删除**（只删预览确认过的集合） |
| S13 | 文件被占用 / 权限不足 | — | — | 单项失败，进入部分成功结果，可重试；重试幂等 |
| S14 | 中央仓库已空、无残留 | — | — | 预览显示"无需清理"，确认按钮禁用 |
| S15 | 已禁用 / 未检测到的 Agent、自定义 Agent | — | — | 同样扫描其目录（只要目录存在） |
| S16 | SSH / WSL 目标 | — | — | 仅作用于当前目标的 DB 与中央根；不影响 Local，反之亦然 |

## 验收标准

- [ ] Central Skills 页面工具栏 `⋯` 菜单出现危险样式的"一键清理…"项；中央仓库为空时的空状态也能进入
      同一流程（S5 场景下用户看不到任何卡片）。
- [ ] 打开后先展示预览：中央 skills 数、各 Agent 将删除的链接数、copy 安装数（默认保留，可按 Agent 勾选）、
      项目链接数、孤儿链接数、中央未登记条目数、跳过的未托管目录数、待恢复日志数。
- [ ] 确认需要输入确认短语；预览为空时确认按钮禁用；取消不调用 apply。
- [ ] 执行期间显示进度（已完成/总数、当前阶段），可取消；取消在条目边界生效，已提交的删除不回滚。
- [ ] 结果展示成功数、失败数及失败条目（`skill_id`/路径 + 稳定错误码），部分失败时对话框保持打开并可重试。
- [ ] S1–S16 均有后端自动化测试（TempDir + `mem_pool`/`file_pool`，不得使用真实 `~/.skillsmanage`）。
- [ ] 性能：Local 下 1000 个中央 skill × 6 个 Agent 的预览 < 2s（release 构建，SSD），执行阶段每项不做重复的
      全量 DB 查询；前端只发起一次 preview 和一次 apply 调用。
- [ ] 执行完成后只触发一次刷新（skills 列表、平台计数），不逐项刷新。
- [ ] 操作日志记录 `central.clear_all`，只含目标类型与计数，不含路径、URL、skill 内容。
- [ ] 所有用户可见文本走 `src/i18n/`（中英文）；README / README_CN 如提及删除能力需同步。
- [ ] 新增 Tauri 命令后运行 `pnpm docs:gen` 并提交生成文件；`just ci` 通过。
