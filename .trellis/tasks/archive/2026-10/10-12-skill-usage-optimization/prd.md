# Skill Usage 界面与性能优化

## 目标与价值

优化 `/usage` 的空间利用、信息层级和响应速度，让用户在 Windows 桌面窗口中快速读懂技能调用、匹配状态和近期活动。完整覆盖用户提出的四项问题：顶部大面积空白，标签/数字/按钮观感，右下热力图空白，以及计算复杂度与扫描速度。

规划及实施均已获用户授权。2026-10-13 用户人工验证后要求按当前结果收尾；完整证据与接受的限制见 `research/integration-verification.md`。

## 背景与已确认事实

- 用户截图是视觉基准，原图为 2542×1378；截图像素不等同 CSS 像素或 Windows 逻辑窗口大小。
- KPI 数字按内容宽度聚拢，但背景和边界横跨整行：`src/components/usage/UsageMetricStrip.tsx:31`。页头、平台筛选和单独 KPI 条叠加占用首屏高度：`src/pages/SkillUsageView.tsx:84`、`:173`。
- 右栏采用可无限增大的比例轨道，热力图固定格子，二者宽度失配：`src/pages/SkillUsageView.tsx:186`、`src/components/usage/ActivityHeatmap.tsx:16`。月份使用单周宽度标签，有相邻月份重叠风险：`ActivityHeatmap.tsx:85`、`:179`。
- 热力图在每个非零格子里重新复制并排序同一组计数：`ActivityHeatmap.tsx:114`、`:210`。排行榜已有排序 memo，但仍全量挂载行：`src/components/usage/SkillUsageTable.tsx:35`、`:136`。
- 扫描已有 TTL、文件缓存、并发和过期缓存后台刷新。剩余成本及完整性风险见 `research/performance-analysis.md`，不能把已有优化重新当成新增方案。
- 最小 Windows 窗口为 900×600：`src-tauri/tauri.conf.json:20`。排版必须继承用户字体、主题和根字号设置。

## 验收标准

- [x] AC1，覆盖 R1：默认字号、无状态横幅、≥1280 宽窗口，页面标题顶部到排行榜卡片顶部的 CSS 高度相对同状态基线减少至少 25%；保留范围、target、刷新时间与刷新入口。窄窗不以裁切控件达标。
- [x] AC2，覆盖 R2：数字使用 tabular-nums，表格数字右对齐；筛选选中态、禁用态、焦点态和操作按钮可辨；决策标签至少 text-xs；实际主题背景上的普通文本对比度达到 4.5:1。
- [x] AC3，覆盖 R3：宽屏右栏可用宽度受控，热力图轴与网格外框占卡片内容宽度至少 80%；图例贴合图形边界，月份不重叠，112 天和零调用天全部保留。满足已有固定格子、无 aspect-square/1fr 和无 row-span 耦合契约。
- [x] AC4，覆盖 R4：提供同机同 fixture 的 before/after 性能报告；支持文件缓存的 Local provider 无变更暖扫的事件表写入行数为 0；单个文件变更只更新其受影响归属/去重组，不重写无关事件；所有结果与全量参考实现等价，失败不能丢失旧数据。Remote 和无文件增量能力的 provider 保留安全回退。
- [ ] AC5，覆盖 R4：热力图从逐格排序收敛到每次数据变更至多一次阈值排序；缓存页读取、平台切换和 10k 行排序/渲染分别测量，不将历史 benchmark 数字当成当前收益。
- [x] AC6，覆盖 R1-R4：子任务验收完成后，集成浏览器矩阵和 Windows WebView2 关键路径通过，`just ci` 通过；原生/安装包/外部 provider 未验证项独立说明。

详细性能目标与视觉矩阵由各子任务 PRD 拥有。不得通过删除历史、截掉榜单、跳过 provider、隐藏零值或缩短 16 周范围取得空间/速度改善。

## 范围与边界

包含 `/usage` 及必要的 usage 状态、Rust service/repository、合成性能 fixture、定向测试和契约更新。现有三态匹配、全历史统计、最近 20 次、16 周活动、未使用技能及解绑行为均保留。

不包含全应用换肤或字体替换、新统计产品功能、provider 扩展、日志内容采集、远端部署、发版或发布。不为消除空白增加装饰图表，不添加第三方图表/虚拟化依赖作为默认方案。
